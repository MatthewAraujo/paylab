# F11 — Historical trends

## Objective

Implement the Trends route: choose a scenario, metric, and optional dimension and see its history across compatible completed Runs with exact values, the Baseline marked, incomplete Runs as markers, and excluded Runs listed with reasons.

## Acceptance Criteria Served

US-83..90.

## Affected Files / Areas

- Trends route, selectors backed by the query string, an accessible SVG chart, and an exact-value table.

## Test-First Plan

- Component and route tests: selectors read and write the address; the chart plots only the API's points in Run order with straight segments and never joins across an exclusion; the Baseline is drawn with a distinct marker and label when it is one of the points; incomplete Runs appear as events without values; excluded Runs are listed with their reason.
- The unit and desirable direction are stated; the exact-value table lists run, value, commit, time, and note and carries all the information of the chart; nothing depends on hover or color.
- Edge states: one point, no points, an unknown scenario, only imported points, and a dense history.

## Implementation Notes

- No charting dependency: SVG and HTML primitives, with labelled axes and a table alternative. Reconsider only if these prove insufficient.
- The x position is the Run order because imported Runs can share a recorded date; exact timestamps stay in the table.

## Dependencies

F2, F3, F4.

## Completion Signal

A developer can inspect a metric's compatible history without relying on color or pointer interaction; tests pass.
