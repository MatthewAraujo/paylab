# T13 — Experiments: index design and pagination cost

## Objective

Measure and document, with `EXPLAIN (ANALYZE, BUFFERS)`, why the Balance, history, Payment list and report queries are fast or slow, and which indexes earn their cost.

## Acceptance Criteria Served

US-75..78.

## Affected Files / Areas

- Benchmark scripts and result notes; ADR files for decisions that become permanent; at most one migration for indexes that the results justify.

## Test-First Plan

The plan is the experiment itself, written before running it:
- State a hypothesis per query (expected plan and cost) before measuring.
- Baseline: capture plans on the full dataset with only constraint-provided indexes, for a hot Wallet and a cold Wallet.
- Try, one at a time, a simple index on account, a composite index on account then creation time then id, and a partial index where a status or recent-window predicate helps; capture plan and timing each time and check write cost impact on inserts.
- Keyset versus offset on a hot Wallet at increasing depth; show the plan difference.
- Measure the Balance query alone and under lock contention on a hot Wallet to decide whether materialization is justified by evidence.
- Add an automated regression test for any adopted index that asserts the plan uses it for the documented query on a fixture large enough to make the planner choose it, or state why this is infeasible.

## Implementation Notes

- Use the `postgres-index-design` and `postgres-query-analysis` skills when interpreting plans.
- Adopt an index only when the measurement shows a clear win and the write cost is acceptable; otherwise document why not.
- Write the outcome of each decision as an ADR (problem, measurement, alternatives, choice, guarantee, cost) because this reasoning is the deliverable of the month.
- If materialization looks warranted, only document it as a proposal; implementing it is outside this plan.

## Dependencies

T11, T12.

## Completion Signal

A results document with plans and timings exists, adopted indexes are in a migration with justification, and one ADR per adopted or rejected major decision is recorded.
