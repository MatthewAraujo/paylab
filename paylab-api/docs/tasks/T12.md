# T12 — Benchmark dataset and tooling

## Objective

Provide a reproducible, skewed benchmark dataset generated inside PostgreSQL, a dedicated benchmark database, and helpers to capture query plans.

## Acceptance Criteria Served

US-71..75.

## Affected Files / Areas

- A benchmark scripts folder with versioned SQL seed scripts and a small runner script.
- Compose or script support for a separate benchmark database.
- A short benchmark guide documenting how to load data and capture plans.

## Test-First Plan

Validation rather than unit tests, because this is tooling:
- After loading a small parameterized run (for example 10 thousand Payments) the counts of Payments, Ledger Transactions and Entries match the expected ratio (two entries per settled Payment).
- The global invariant helper (T4) is clean on the generated data.
- Skew check: the top 1% of Wallets hold roughly half of the entries (assert within a tolerance).
- Determinism: two runs with the same seed produce identical aggregate counts.
- Full-size run (about 1 million Payments, 2 million Entries, about 1,000 Wallets, about 50 Merchants) completes in reasonable time on a laptop.

## Implementation Notes

- Generate with `generate_series` and a seeded random source, in bulk, inside PostgreSQL; bypass the application.
- Disable nothing that weakens integrity: the generated data must pass the triggers, so build balanced Ledger Transactions.
- Run `ANALYZE` after loading, and make it part of the runner.
- The benchmark database is separate from development and test databases; connection settings come from dedicated environment variables.
- Record machine and PostgreSQL version alongside results so numbers are interpretable later.

## Dependencies

T4, T11.

## Completion Signal

The small run passes all validations and the full run loads; the guide reproduces the setup from scratch.
