# B2 — Build the safe Run lifecycle and local publication shell

## Objective

Implement the terminal-only `benchmark:run` command shell: clean-worktree enforcement, exclusive lock, optional note, progress persistence, child-process capture, sanitization, stale-run recovery, local Artifact layout, and atomic terminal Summary publication. Scenarios are pluggable so the shell can be tested with a fake suite.

## Affected Files / Areas

- `package.json` script `benchmark:run`, and a CLI entrypoint beside `bench/run.ts`.
- Git preflight adapter (tracked and untracked changes; ignored Artifact files excluded).
- Local Run repository, exclusive lock, atomic writes, Artifact writer, log sanitizer, and recovery.
- `.gitignore` rule for the local Artifact root; environment example for the Artifact root and versioned Summary directory.
- Integration tests under `test/integration/` or `test/scripts/` (prior art: `test/scripts/demo-guard.spec.ts`, `test/integration/demo-seed.spec.ts`).

## Test-First Plan

Process-boundary integration tests in a temporary Git repository with a temporary Artifact root and controlled fake scenario processes. Failing tests first for:

- dirty tracked file and untracked file rejection; an ignored Artifact file does not block;
- optional note captured in the Summary;
- second invocation exits non-zero and reports the active Run and stage;
- `RUNNING` state and progress visible before the first scenario finishes;
- successful fake suite gives a `COMPLETED` Summary and generated-file report with a suggested commit message;
- child failure and killed process give `INCOMPLETE` with retained completed measurements and failure details;
- stale `RUNNING` record recovered as `INCOMPLETE` with interruption evidence;
- database URLs, credentials, and configured secrets redacted in stored logs;
- Summary write is atomic and no Git commit is made;
- a pending uncommitted Summary or Baseline change blocks the next Run.

## Implementation Notes

- Resolve and validate every storage and destructive path before use.
- Atomic replace for the mutable running state and for the immutable final Summary.
- Redaction scope: configured secrets plus recognizable database URL and credential forms.
- Scenario execution is injected; B3 and B4 register the real scenarios.
