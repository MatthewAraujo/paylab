# T1 — Prune the copied base down to the technical spine

## Objective

Turn the copy of the reference project into a clean PayLab skeleton: remove every Quintal Agro Pet business context and the infrastructure PayLab does not use in September, rename the project, and leave an app that boots with only a health endpoint.

## Acceptance Criteria Served

US-80, US-83 (structured logging and error translation inherited and still working), and the "Out of Scope" list of the PRD (no Redis, storage, geocoding, WebSocket, Better Auth).

## Affected Files / Areas

- Remove: the whole Quintal Agro Pet domain folder, all HTTP controllers, presenters and gateways of those contexts, all `*.module.ts` of those contexts, geocoding, storage, cache/Redis, Better Auth (module, guards, env validation), the Prisma repositories and mappers, all domain/integration/e2e/infra tests and support files tied to them, and the three scripts in the scripts folder.
- Keep and adapt: `src/core/` (Either, entities, errors, events, WatchedList if unused can be dropped), `src/infra/env`, `src/infra/observability`, `src/infra/http/security`, `src/infra/http/error-translation` (strip messages of removed contexts, keep the mechanism), `src/infra/http/pipes` (Zod validation, pagination helper), `src/shared/http`, health controller and module, app factory (remove the Socket.IO adapter and Better Auth logging branch), `main.ts`.
- Configs: `package.json` (rename to `paylab-api`, drop unused dependencies such as socket.io, AWS S3 client, ioredis, resend, better-auth and its Nest adapter, socket.io-client), `docker-compose.yml` (rename container, database and network), env example files (drop unused variables, add `DATABASE_URL`), `.github/workflows/ci.yml` names, `railway.json` (delete if not used), `.gitignore` check.
- Prisma: replace `prisma/schema.prisma` with an empty datasource and generator, delete all existing migrations and the seed file.
- New domain root: `src/domain/paylab/{application,enterprise}` created empty with placeholder README-free structure (no files needed until T5).

## Test-First Plan

- Keep or rewrite the health e2e test first: it must pass against the pruned app before and after removal work.
- Keep the surviving unit specs (Either, domain-events if the events module is kept) green.
- Add a small unit spec for the env schema (valid and invalid `DATABASE_URL`) since the env schema is rewritten.
- No database is required in this task; e2e for health must not need PostgreSQL. If the Prisma service forces a connection at boot, make it lazy or exclude it from the health-only boot until T3.

## Implementation Notes

- Use the reference project one directory up as a read-only guide; never modify it.
- Do the removal in reviewable steps (domain and infra removal, then dependencies, then configs) and run typecheck between steps.
- Remove dead error-message maps rather than leaving unreachable translations; keep the translation mechanism because T9 reuses it.
- Do not introduce any PayLab business code here.

## Dependencies

None.

## Completion Signal

`pnpm install`, `pnpm typecheck`, `pnpm lint` and the surviving tests pass; `pnpm dev` boots and `GET /health` answers; a repository-wide search finds no reference to Quintal, agropet, better-auth, socket.io, redis, geocoding or storage code.
