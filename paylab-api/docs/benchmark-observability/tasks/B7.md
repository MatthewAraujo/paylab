# B7 — Add versioned Baseline selection

## Objective

Let a development-only API write select one eligible completed Run as the versioned Benchmark Baseline without mutating any Run evidence, and expose the current Baseline and pending Git state.

## Acceptance Criteria Served

US-30, US-54, US-55, US-56, US-57, US-58, US-65.

## Affected Files / Areas

- Baseline reference schema and repository with atomic write, in the benchmark area.
- Baseline read and write endpoints, DTOs, and Swagger metadata in the B6 module.
- Git pending-state check shared with B2.
- Unit and e2e tests.

## Test-First Plan

- Failing tests first: select a completed native and an imported Run; reject running, incomplete, and missing candidates; Summaries unchanged after selection; pointer replaced atomically; response reports the pending Git change; the next executor invocation is blocked until clean; write refused when the capability is off.

## Implementation Notes

- The API never commits the Baseline reference.
- Lineage and compatibility use B1 rules.

## Dependencies

B1, B2, B6.

## Completion Signal

The API persists, reads, replaces, and discloses a reviewable Baseline pointer while Runs stay immutable; e2e passes.
