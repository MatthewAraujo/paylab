# F1 — Refresh the contract and derive the Benchmarks capability

## Objective

Bring the API's benchmark routes into the committed OpenAPI snapshot and generated types, and extend capability detection so the console knows, from the contract, whether the Benchmarks area can exist.

## Acceptance Criteria Served

US-4, US-96 (contract-derived availability, and the foundation of every typed read).

## Affected Files / Areas

- `openapi/paylab.json` and `src/api/generated/schema.d.ts` (refreshed with `pnpm sync:api`).
- `src/api/capabilities.ts` and its test, `src/api/current-capabilities.ts`, and the tests that assert the capability object.
- The comment in `capabilities.ts` that says the console never uses write operations (the Baseline selection is the single, deliberate exception).

## Test-First Plan

- Failing capability tests first: a document with every benchmark route typed gives `benchmarks: true`; a document without them, or with a route that has no JSON response schema, gives `false`; existing capabilities are unchanged; the Baseline `PUT` being absent does not disable read-only Benchmarks but disables only the Baseline action (expose it as a separate capability flag).
- Then refresh the snapshot and regenerate the types; add a test that the generated schema contains the benchmark paths and their key response types so a stale snapshot fails loudly.

## Implementation Notes

- Precondition: a local API running with the benchmark capability on (`NODE_ENV=development`) and reachable. Starting the API connects it to the developer's development database as it always does; ask before doing so if it is not already running.
- The refresh must be additive: review the diff and confirm no financial route changed.
- Do not handwrite any benchmark type; everything downstream imports the generated ones.

## Dependencies

None.

## Completion Signal

The snapshot and generated types include `/v1/benchmarks/*`; `deriveCapabilities` reports `benchmarks` (and the separate Baseline-write flag) from the contract; `pnpm typecheck`, `pnpm test`, and `pnpm lint` pass.
