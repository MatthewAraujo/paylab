# F4 — Navigation, route frames, design-system pieces, and shared states

## Objective

Add Benchmarks to the existing shell and create the route frames, the benchmark badges and small shared components, and the first-class shared states that every screen reuses.

## Acceptance Criteria Served

US-1, US-2, US-3, US-4, US-5, US-6, US-7, US-8, US-32, US-91, US-95.

## Affected Files / Areas

- `src/components/app-shell.tsx` navigation registry (desktop sidebar and mobile Sheet share it) and its test.
- New routes under the console group: overview, comparison, trends, and Run detail, each a frame with the shared page header, metadata, and the sub-navigation between Overview, Comparison, and Trends built from links with `aria-current`.
- `src/components/ui/badge.tsx` variants and new small components: Run status, provenance, Performance Change, compatibility, monospace metric value, copyable identifier.
- Shared states: capability unavailable in local development, API unreachable with retry, loading skeleton, empty history, error notice, refresh-failed notice, unreadable-records notice.

## Test-First Plan

- Failing app-shell test that Benchmarks appears in both the desktop navigation and the mobile sheet and is current on every benchmark route.
- Badge and state tests assert text and shape cues (not color): every lifecycle state, provenance, change, and compatibility label is present as text.
- The copyable identifier copies the full value and announces it politely.
- State components render the approved English copy: local-development-only wording without production-enable prompts, a note that Runs start from the terminal, and no "run", "cancel", or "pause" control anywhere.

## Implementation Notes

- Read the bundled Next.js 16 guides before writing route code (`AGENTS.md`): `params` and `searchParams` handling, the Suspense requirement of `useSearchParams`, and metadata.
- Map the prototype palette onto existing tokens; add only semantic improved and running colors that no existing token expresses. Keep the `text-xs` baseline; no new web fonts.
- The prototype is a visual reference only: no code, markup, or static data from `PayLab-Benchmarks-source/` is imported.

The four routes render inside the shell with correct navigation and current-page marking; the shared pieces and states exist with tests; no benchmark feature yet depends on ad hoc markup.
