# B1 — Define and validate the benchmark evidence contract

## Objective

Create the versioned schemas and pure rules for Benchmark Runs, Summaries, scenarios, protocols, metrics, environment and dataset fingerprints, Artifact references, compatibility, Baselines, and Performance Change math.

## Acceptance Criteria Served

US-5, US-6, US-38, US-39, US-40, US-41, US-42, US-48, US-49, US-50, US-51, US-54, US-65.

## Affected Files / Areas

- New benchmark contract modules under `src/domain/` (or a new benchmark area beside it), with no Nest, Prisma, filesystem, or HTTP imports.
- Zod schemas with an explicit schema version, and a deterministic JSON serializer.
- Shared Summary fixtures under `test/support/` reused by B2, B5, B6, and B7.
- Unit tests under `test/domain/` following the existing layout.

## Test-First Plan

- Failing tests first: valid native, imported, `RUNNING`, `COMPLETED`, and `INCOMPLETE` records parse; malformed, unsafe (path-like identifiers), and unknown-schema-version records are rejected.
- Metric direction tests: higher-is-better and lower-is-better produce the correct improved/regressed sign; stable at exactly ±5%; zero reference and absent values return "not comparable" rather than a number.
- Compatibility tests: unchanged, new, removed, changed fingerprint, dataset-incompatible, and environment-incompatible scenarios.
- Determinism tests: same input gives byte-identical serialization and identical fingerprints regardless of key order.
- Default comparison pair selection: newest completed Run and its previous compatible Run; incomplete Runs excluded.

## Implementation Notes

- Keep the contract generic. T13/T14-specific configuration lives in the scenario payload, never in metric keys.
- Summary roles are explicit metadata; nothing infers headline metrics from names or order.
- Absent imported measurements are absent, never zero.
- Lifecycle transitions are explicit and a terminal Summary cannot be modified.

## Dependencies

None.

## Completion Signal

Every evidence record and comparison decision can be validated and calculated in unit tests with no filesystem, database, or HTTP dependency; `pnpm test`, `pnpm typecheck`, and `pnpm lint` pass.
