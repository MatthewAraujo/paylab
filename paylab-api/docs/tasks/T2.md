# T2 — Test infrastructure: Testcontainers and suite layout

## Objective

Provide a real, disposable PostgreSQL for every database-backed suite and split the test runner into the layers the PRD defines, so all later tasks can write tests without further setup.

## Acceptance Criteria Served

US-81 (migrations build the schema from empty), US-82 (global invariant check hook point), US-84 (CI gate), and the Testing Decisions of the PRD.

## Affected Files / Areas

- `package.json`: add `@testcontainers/postgresql` and `testcontainers`; scripts for `test` (unit), `test:integration`, `test:e2e`, `test:concurrency`; keep `typecheck` and `lint`.
- Vitest configs: one per layer (unit, integration, e2e, concurrency) with a shared global setup that starts one PostgreSQL 16 container per run, applies migrations with `prisma migrate deploy`, exports `DATABASE_URL` and stops the container at the end.
- `test/setup` helpers: a database helper that truncates application tables between tests (truncate is allowed even after T4, see its notes), a Nest app builder for e2e, and a placeholder for the global invariant check (filled in T4).
- `.github/workflows/ci.yml`: replace the Postgres service container with Docker-based Testcontainers (GitHub runners already provide Docker), keep separate jobs for lint, typecheck, unit plus integration plus e2e; make the concurrency job separate and non-blocking.
- Directory layout under `test/`: `domain/`, `integration/`, `e2e/`, `concurrency/`, `support/`.

## Test-First Plan

- A smoke spec per layer: unit (trivial pure test), integration (connects to the container and runs `SELECT 1`), e2e (boots the app and calls health), concurrency (opens two connections and runs in parallel).
- Prove isolation: two consecutive specs must not see each other's rows after the truncate helper runs.
- Prove the migration step runs from an empty database (an empty baseline is fine until T3).

## Implementation Notes

- Testcontainers requires Docker locally and in CI; document this in the developer notes later (T16).
- One container per test run, not per file, to keep the suite fast; file parallelism stays off for database suites.
- Concurrency tests need several real connections; expose a helper that creates independent connection pools against the same container.
- Keep the reference project's habit of an env-defaults setup file so tests never read a developer `.env`.

## Dependencies

T1.

## Completion Signal

Each of the four test commands runs its smoke spec green locally with Docker, and CI runs the same layers green on a pull request.
