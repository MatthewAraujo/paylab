# T6 — Settlement: lock, funds check and atomic ledger write

## Objective

Implement the Settlement (ADR 0001, ADR 0002): in one transaction, lock the source Wallet, compute its Balance from the ledger, write the Ledger Transaction and Entries and finish the Payment, or fail it with `INSUFFICIENT_FUNDS`. Also expose the Balance query.

## Acceptance Criteria Served

US-12, US-13, US-37..41, US-45..46, US-47..51 (behavior; the parallel proof is T10).

## Affected Files / Areas

- Application layer: a Settlement use case and a Balance query use case.
- Infra: Prisma-backed repositories for accounts and payments and a raw-SQL settlement adapter.
- Integration tests for both.

## Test-First Plan

Integration tests against the Testcontainers database, through the use case (no HTTP):
- Wallet with enough funds: Payment ends `SUCCEEDED`, exactly one Ledger Transaction with a debit on the source and a credit on the destination, Balances updated.
- Insufficient funds: Payment ends `FAILED` with `INSUFFICIENT_FUNDS`, no Ledger Transaction is written, Balances unchanged.
- Exactly enough funds succeeds and leaves a zero Balance.
- Clearing-sourced Payment: succeeds with no funds check and no lock, debiting clearing and crediting the Wallet.
- Wallet to clearing (withdrawal) obeys the funds check.
- Settling an already terminal Payment is rejected and changes nothing.
- A settled Payment references its Ledger Transaction; a failed one references none.
- Balance query equals credits minus debits and is zero for a new Wallet.
- The global invariant helper is clean after each test.

## Implementation Notes

- Interactive Prisma transaction in `READ COMMITTED`. Sequence: move the Payment to `PROCESSING`, then only for a Balance Consumer run `SELECT ... FOR NO KEY UPDATE` on the source Wallet row, then sum the Balance with raw SQL, then either insert the Ledger Transaction and two entries and mark `SUCCEEDED`, or mark `FAILED`.
- Lock only the source; never lock the destination. A clearing source takes no lock.
- All money arithmetic in integers; convert database 64-bit integers at the mapper boundary.
- Keep the raw SQL in one adapter with comments explaining why the weak lock mode was chosen (ADR 0002), because it is study material.
- Concurrency proof and crash-resume behavior are exercised in T9 and T10, not here.
