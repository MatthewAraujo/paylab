# B6 — Expose a development-only benchmark read API

## Objective

Add typed Nest endpoints for capability, paginated Runs, Run detail and progress, comparison compatibility and default pair, trend series, and sanitized Artifact metadata, bounded content, and download, all gated by a development-only capability.

## Acceptance Criteria Served

US-16, US-23, US-45, US-46, US-47, US-48, US-49, US-50, US-52, US-53, US-59, US-60, US-61, US-62, US-63, US-64, US-65.

## Affected Files / Areas

- `src/infra/env/env.ts` and `.env.example` (capability flag, Artifact and Summary roots).
- New benchmark HTTP module, controller, read adapters, presenters, and Swagger metadata beside `src/infra/http/`; registration in `src/infra/app.module.ts` and `src/infra/app.factory.ts`.
- OpenAPI helpers in `src/infra/http/openapi/`; extend `test/e2e/openapi-contract.e2e-spec.ts`.
- New e2e specs with real Summary and Artifact fixtures (prior art: `test/e2e/history.e2e-spec.ts`, `payments-list.e2e-spec.ts`).

## Test-First Plan

- Failing e2e tests first: disabled in production mode; enabled in development; list ordering and pagination; detail and active progress; imported and incomplete Runs; missing Artifact response; log content, bounded read, and download; path traversal rejection; redaction defense; compatibility metadata and default pair; trend series with incomplete markers and no metric points; malformed Summary isolated; no route starts a Run; works without a benchmark database and without Merchant authentication.

## Implementation Notes

- Capability defaults off outside development; clients never pass filesystem paths.
- Serve only records that pass B1 validation; sanitize again before exposure.
- Bounded payloads: paginated history, capped inline logs, streamed downloads.
- Follow existing pagination and error-translation conventions.

## Dependencies

B1, B2, B5.

## Completion Signal

OpenAPI fully describes a safe local read API and production-mode e2e proves it is unavailable; `pnpm test:e2e` passes.
