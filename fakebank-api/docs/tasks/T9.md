# T9 — Docker Compose (standalone and workspace) and documentation

## Objective

Run FakeBank with one Docker Compose command on its own, and start it with its own database in the workspace development stack, without changing the PayLab services.

## Acceptance Criteria Served

- AC-32 (standalone Compose: FakeBank and its PostgreSQL, migrations applied, `/health` and `/docs` on port 4000).
- AC-33 (workspace stack: `fakebank` and `fakebank-postgres`, `127.0.0.1:4000`, database not published, own volume, source reload, PayLab unchanged).
- Documentation side of AC-34 (development key defaults confined to development configuration).

## Affected Files / Areas

- `fakebank-api` development Dockerfile (mirror `paylab-api/Dockerfile`, including `procps` for Nest watch-mode restarts; see the workspace `CONTEXT.md` reload note) and `.dockerignore`.
- `fakebank-api/docker-compose.yml`: API plus PostgreSQL, migrations on start, lab enabled, a documented development Client key hash.
- Workspace `compose.yaml`: `fakebank` and `fakebank-postgres` services and a `fakebank-postgres-data` volume; migrations before start; `src` mounted for reload; no changes to `postgres`, `demo-init`, `api` or `ui`.
- Workspace `PROJECT.md` (the workspace now contains three applications; port 4000; how to call FakeBank with the development key) and `fakebank-api/PROJECT.md` (Docker commands).

## Test-First Plan

Compose stacks have no automated test layer in this workspace; validate with documented commands instead:

- AC-32 → `docker compose up --build` in `fakebank-api`, then `curl` `/health` and `/docs` on port 4000, and one authenticated `POST /v1/transactions` with the development key → manual → image missing migrations or env.
- AC-33 → `docker compose config` at the workspace root shows FakeBank published only on `127.0.0.1:4000` and `fakebank-postgres` with no ports → manual → database exposed on the host.
- AC-33 → `docker compose up --build` at the root: PayLab console and API still answer as before (`localhost:3000`, `localhost:3333/health`) and FakeBank answers on 4000 → manual → PayLab stack regressed.
- AC-33 → editing a FakeBank source file reloads the service (same approach as `scripts/check-docker-reload.py`; extending the script is optional) → manual → stale code in development.
- AC-33 → `docker compose stop` then `up` keeps FakeBank data (volume) → manual → data lost on restart.

## Implementation Notes

- The development Client key is for local use only; document it as such and never reuse it in a non-development configuration.
- Read every script the Dockerfile runs before building (global guardrail).
- PayLab does not call FakeBank yet; do not add environment variables to PayLab services.

## Dependencies

T3 (authenticated creation and migrations exist to smoke test).

## Completion Signal

Both Compose commands start healthy stacks; the manual checks above pass and are recorded in the task run summary; the PayLab services in the workspace `compose.yaml` are byte-for-byte unchanged.
