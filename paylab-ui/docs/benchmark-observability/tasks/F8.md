# F8 — Artifact viewer

## Objective

Let the developer read sanitized Artifacts in the browser: bounded loading in chunks, wrap control, copy, download, and honest loading, error, and missing-file states, always as plain text.

## Acceptance Criteria Served

US-52..58 (and the log links of US-28 and US-50).

## Affected Files / Areas

- Artifact viewer dialog and its trigger from the Run detail inventory and the active-Run panel; a local dialog component built on the existing Radix dependency.

## Test-First Plan

- Component tests with the request stub: opening loads the first chunk; "load more" requests the next offset until the API reports the end; content that looks like markup (a script tag, an HTML link) is displayed as literal text; wrap toggles the layout; copy places the loaded text on the clipboard with polite feedback; download is a link to the API's download route; the retained-locally note is present.
- States: loading, fetch error with retry, an unavailable file (the API's specific answer) explained as not available on this machine, and a Run or Artifact that does not exist.
- Keyboard: focus moves into the dialog, is trapped while open, the log region is reachable and scrollable without trapping, and focus returns to the trigger on close.

## Implementation Notes

- The viewer never assumes the whole file is loaded; the chunk size comes from the contract's bounds.
- No syntax highlighting; no rendering of Artifact content as HTML.

## Dependencies

F2, F4.

## Completion Signal

Any listed Artifact can be inspected, copied, and downloaded safely, and every failure mode is explained where it occurs; tests pass.
