# F6 — Active Run: progress and recent log

## Objective

Show a Run that is executing, refreshed by bounded polling: status, scenario counts, current scenario, elapsed time, overall progress, the most recent sanitized log output, and honest freshness information.

## Acceptance Criteria Served

US-25..31.

## Affected Files / Areas

- Active-Run section of the overview and the same panel in the Run detail, using the polling parameters from F2.

## Test-First Plan

- With fake timers and the request stub: a RUNNING Run renders `RUNNING`, completed, active, pending, and failed counts, the current scenario, elapsed time, and a progress representation with a text value.
- Polling starts only while the Run is running and its owner is alive; each refresh keeps the visible content (no clearing, no full-page loading) and updates the last-successful-refresh time; the states say "polling", never "live".
- Polling stops when the Run becomes COMPLETED or INCOMPLETE, and when the record is reported abandoned (an explanation replaces the progress); a failed refresh keeps the last data and says so.
- The recent log is the tail of the active scenario's log Artifact read through the size and bounded offset, with a partial first line dropped, rendered as escaped text.
- Announcements: a single restrained polite status for changes of scenario, not per log line.

## Implementation Notes

- Interval and stop rules live in one place and are covered by unit tests; no WebSocket or server-sent events.
- Provide the link to the complete Run detail and to the full log viewer (F8).

## Dependencies

F5.

## Completion Signal

An active Run can be followed from the console without manual refresh; polling provably stops in every terminal or abandoned state; tests pass.
