# T3 — Production-local stack end to end

## Objective
Add `compose.production.yaml` so `docker compose -f compose.production.yaml up --build -d` starts PostgreSQL, the initializer, the API and the console with isolated volumes, loopback ports, healthchecks, dependency ordering and a required gitignored `.env.production`. Add a repeatable smoke check.

## Acceptance Criteria Served
AC-2, AC-3, AC-4, AC-7, AC-10, AC-12, AC-13 in ../PRD.md.

## Affected Files / Areas
New root `compose.production.yaml`, `.env.production.example`; root `.gitignore`; new `scripts/check-production-stack.py` (pattern of `scripts/check-docker-reload.py`). Uses the T1 and T2 Dockerfiles.

## Test-First Plan
- AC-2 → both Compose files pass `config --quiet`; ports bound only on 127.0.0.1; no PostgreSQL host port → Compose → catches public binding.
- AC-3 → production project name and volumes differ from `paylab-local`'s → `docker volume ls`/Compose → catches shared or reused development data.
- AC-4 → first startup seeds Demo Store; authenticated API read with the generated key succeeds; console renders Demo Store data → HTTP → catches broken key sharing or init ordering.
- AC-7 → initializer runs `prisma migrate deploy` before API start on each startup; API depends on its successful completion → Compose/logs → catches API serving before migrations.
- AC-10 → all three long-running services become `healthy`; console starts only after a healthy API → `docker compose ps` → catches missing or wrong healthchecks.
- AC-12 → key absent from console HTML; volume mounted read-only in console; key not in tracked files or `docker inspect` build args → HTTP/inspect/git grep → catches leakage.
- AC-13 → without `.env.production`, Compose fails before starting containers naming the file; `.env.production` is ignored by git; example has only safe values → Compose/git → catches committed secrets or silent defaults.

## Implementation Notes
Keep service name `postgres` and database `paylab_demo` (initializer guard). Use a distinct Compose project name and named volumes. Service-level required env file for postgres, initializer and API. API: `NODE_ENV=production`, `FRONTEND_URL=http://localhost:3000`, port 3333. Console: `PAYLAB_INTERNAL_API_URL=http://api:3333`, key read from the read-only credential volume and exported only to the server process. Console healthcheck: home route without following redirects. Add `.env.production` and `backups/` to the root `.gitignore` without removing existing entries. Smoke script: standard library only, never removes volumes, never prints the key. Development and production-local stacks share ports; stop the development stack first.
