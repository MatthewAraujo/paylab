# T1 — Run the complete local demo stack with Docker

## Objective
Provide one-command development startup across the existing sibling repositories.

## Acceptance Criteria Served
AC-1 through AC-5 in ../PRD.md.

## Affected Files / Areas
Root Compose and documentation; per-repository Dockerfiles and ignore files; API Docker demo initializer; UI server-client environment selection and regression test.

## Test-First Plan
- AC-1 → complete startup → Compose/HTTP → catches missing dependencies or incorrect service ordering.
- AC-2 → edited source is served → development server/source bind mounts → catches image-only source.
- AC-3 → internal server URL and explicit override precedence → existing server-client test → catches server requests to container localhost.
- AC-3 → authenticated UI → rendered page and API → catches missing/wrong key or public credential leakage.
- AC-4 → second startup preserves account ids/counts → Compose/HTTP → catches duplicate seeding or lost credentials.
- AC-5 → runnable instructions → documentation review.

## Implementation Notes
Keep current PostgreSQL Compose untouched. Use a separate named volume; no destructive commands. Reuse demo seed functions without loosening host demo guards. Do not print credentials. Fail on inconsistent database/key state.

## Dependencies
None.

## Completion Signal
Compose startup and restart validated, targeted tests pass, commands documented; any environmental limitations recorded explicitly.
