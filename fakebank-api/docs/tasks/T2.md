# T2 — Provider Transaction state machine

## Objective

A pure module, with no Nest or Prisma dependency, that owns the Provider Transaction status model and the Provider Transaction Events each transition produces.

## Acceptance Criteria Served

- AC-26 (only `PROCESSING → SUCCEEDED` and `PROCESSING → FAILED` are allowed).
- Supplies the event rules used by AC-27 (implemented in T3 and T7).

## Affected Files / Areas

- A domain module in `fakebank-api/src` for the Provider Transaction: statuses (`PROCESSING`, `SUCCEEDED`, `FAILED`), creation (always `PROCESSING`, emitting `transaction.processing`), and transitions to a terminal status (emitting `transaction.succeeded` or `transaction.failed`, setting `completedAt`).
- Unit tests under `fakebank-api/test`.

If T1 has not landed yet, create only the module and its unit test with the minimal Vitest setup T1 will own; coordinate so T1's config includes it.

## Test-First Plan

- AC-26 → `PROCESSING → SUCCEEDED` is allowed and produces one `transaction.succeeded` event with `completedAt` set → unit → terminal transition not recorded or timestamp missing.
- AC-26 → `PROCESSING → FAILED` requires a Failure Code and produces `transaction.failed` carrying it → unit → failure without a reason.
- AC-26 → `SUCCEEDED → FAILED`, `FAILED → SUCCEEDED`, `SUCCEEDED → SUCCEEDED`, `FAILED → FAILED` and any transition back to `PROCESSING` are refused with an invalid-transition error and no event → unit → a terminal transaction being rewritten.
- AC-27 → creating a Provider Transaction yields status `PROCESSING` and exactly one `transaction.processing` event → unit → missing initial event.
- AC-27 → creation followed by an immediate decision yields events in order `processing`, then the terminal one → unit → wrong event order.

## Implementation Notes

- Return an Either-style result or a typed error for refused transitions; the HTTP layer (T7) maps it to `409 INVALID_TRANSITION`.
- Event ids and timestamps come from injected functions or arguments so the module stays deterministic in tests.
- Vocabulary from `fakebank-api/CONTEXT.md`: Provider Transaction, Provider Transaction Event, Failure Code.

## Dependencies

None (T1 provides the shared test config; see Affected Files).

## Completion Signal

The unit tests above pass under `pnpm test`; the module imports nothing from Nest, Prisma or `paylab-api`.
