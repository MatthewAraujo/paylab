# T5 — Domain model: Amount, Accounts and the Payment state machine

## Objective

Implement the pure domain layer with no database: the Amount value object, Account kinds, and the Payment aggregate with its state machine and creation rules.

## Acceptance Criteria Served

US-15, US-20..24, US-42..44, US-46 (rule that clearing-sourced Payments skip the funds check is expressed in the domain).

## Affected Files / Areas

- The new PayLab domain root: `enterprise/` (entities, value objects, errors) and `application/repositories` (ports only, as abstract classes following the reference project's pattern).
- Unit specs under the domain test folder.

## Test-First Plan

Pure unit tests, no infrastructure:
- Amount: created from an integer number of centavos; rejects zero, negative, non-integer and unsafe values; addition and comparison behave; never accepts a float.
- Payment creation: rejects same source and destination, non-positive Amount, and mismatched currencies; accepts a valid pair.
- State machine: allows `CREATED → PROCESSING → SUCCEEDED` and `PROCESSING → FAILED` with a reason; rejects every other transition, including any transition out of a terminal state.
- Balance Consumer: a Payment is a Balance Consumer when its source is a Wallet and is not when its source is the External Clearing Account.
- Only BRL is accepted in September.

## Implementation Notes

- Follow the reference project's layering: entities extend the core `Entity` or `AggregateRoot`, expected failures are returned with the core `Either`, and repositories are abstract classes bound in the infra module.
- Use the glossary terms exactly (`Wallet`, `External Clearing Account`, `Balance Consumer`, `Settlement`); no Merchant-facing HTTP concepts here.
- Amount is centavos as an integer; decide the internal numeric type (bigint or safe integer) once and document it; conversion to and from the database 64-bit integer happens only in the infra mapper.
- Ports to declare now: an accounts repository, a payments repository, and a settlement port (interface only; implemented in T6).
