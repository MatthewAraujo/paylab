# T1 — Service skeleton

## Objective

Create the `fakebank-api` NestJS HTTP service with the toolchain, configuration, error envelope, health and documentation endpoints, and the test layers every later task builds on. No payment behavior yet.

## Acceptance Criteria Served

- AC-11 (`GET /health` answers `200` without authentication).
- Foundation of AC-10 (error envelope `{ code, message, retryable, requestId }`, `X-Request-Id` echoed or generated) and AC-12 (`/docs` served).

## Affected Files / Areas

- New workspace folder `fakebank-api/`: `package.json` (pnpm 11, Node 22), TypeScript config, Biome config, Nest CLI config, `mise.toml`, `.env.example`, `.gitignore`.
- Prisma schema and a migrations folder (hand-written SQL migrations are the source of truth, as in `paylab-api`), with an initial empty-or-baseline migration so `prisma migrate deploy` works.
- `src/`: bootstrap and app factory, environment module (Zod-validated: `DATABASE_URL`, `PORT` default 4000, `NODE_ENV`, logging variables mirroring `paylab-api`), database module (Prisma client), HTTP error translation (global filter producing the envelope), request-id handling, health controller, Swagger setup at `/docs`.
- Vitest configs for unit, integration, e2e and concurrency layers; `test/support` with Testcontainers global setup (one PostgreSQL per run, migrations applied) and a `buildTestApp` helper booting the real application module.
- `fakebank-api/PROJECT.md` (stack, structure, commands, environment, local setup).

Prior art to mirror: `paylab-api` `vitest.config.*.ts`, `test/support/global-setup.ts`, `setup-env.ts`, `setup-database.ts`, `app.ts`, `src/infra/env`, `src/infra/http` error translation, `src/infra/app.factory.ts`.

## Test-First Plan

- AC-11 → `GET /health` returns `200` with no `Authorization` header → e2e → health accidentally behind auth or not registered.
- AC-10 → an unknown route returns `404` with the error envelope and a generated `requestId` echoed in the `X-Request-Id` response header → e2e → framework default error bodies leaking instead of the contract.
- AC-10 → a request carrying `X-Request-Id: abc` gets `requestId: "abc"` in the body and the same header back → e2e → correlation id ignored or regenerated.
- AC-10 → an unexpected thrown error becomes `500` with `retryable: true` and no stack trace in the body → e2e (a test-only route or provider override) → internal details leaking, wrong retryable flag.
- AC-12 → `/docs` (and its JSON document) is served → e2e → Swagger not mounted.
- Configuration → boot fails with a clear message when `DATABASE_URL` is missing → unit on the env schema → service starting half-configured.

## Implementation Notes

- Follow ADR 0001: no imports from `paylab-api`; copy and trim what is needed.
- Keep `retryable` derivation in one place (true for `429`, `500`, `503`).
- `pnpm` scripts: `dev`, `build`, `start:prod`, `lint`, `lint:fix`, `typecheck`, `test`, `test:integration`, `test:e2e`, `test:concurrency`, `prisma:migrate`, `prisma:migrate:deploy`.
- Run `pnpm install` only after reading the generated `package.json` scripts (postinstall runs `prisma generate`).

## Dependencies

None.

## Completion Signal

`pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm test:e2e` pass in `fakebank-api`; `pnpm dev` with a local database answers `GET /health` and serves `/docs` on port 4000.
