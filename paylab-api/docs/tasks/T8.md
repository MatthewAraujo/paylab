# T8 — Accounts API: create Wallet, read Account, read Balance

## Objective

Expose Merchant-scoped Wallet endpoints under `/v1`.

## Acceptance Criteria Served

US-7, US-8, US-9..15.

## Affected Files / Areas

- Application layer: create Wallet and get Account use cases (Balance from T6).
- Infra: an accounts controller, request and response schemas with the Zod pipe, a presenter, module wiring.
- E2E tests.

## Test-First Plan

E2E through HTTP against the Testcontainers database:
- `POST /v1/accounts` creates a BRL Wallet for the authenticated Merchant with zero Balance.
- A Merchant can create several Wallets.
- `GET /v1/accounts/:id` returns the Wallet for its owner.
- `GET /v1/accounts/:id/balance` returns credits minus debits after some movements.
- Requesting another Merchant's Wallet, or an unknown id, returns identical not-found responses.
- The External Clearing Account is never returned or creatable through the API.
- Unauthenticated requests return 401.

## Implementation Notes

- Amounts in responses are integers in centavos with an explicit currency field.
- Use the same not-found response for "not yours" and "does not exist" (settles the open detail in the PRD as 404).
- Follow the reference controller pattern (versioned route, guard, Zod pipe, presenter, error translation).

All e2e tests pass and the global invariant check is clean.
