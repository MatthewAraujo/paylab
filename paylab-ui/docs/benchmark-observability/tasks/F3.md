# F3 — Pure benchmark presentation rules

## Objective

Implement, independent of React, every rule that turns evidence into presentation: Performance Change classification, deltas, metric identity, comparison rows and summary counts, headline selection, grouping, and formatting.

## Acceptance Criteria Served

US-10, US-13, US-14, US-15, US-17, US-40, US-41 (grouping), US-65..74, US-96.

## Affected Files / Areas

- New pure modules under `src/features/benchmarks/` and unit tests beside them.
- `src/lib/datetime.ts` and `src/lib/money.ts` are the existing conventions to follow and extend rather than duplicate.

## Test-First Plan

Independent literals, failing first:

- Classification: higher and lower is better; exactly +5% and −5% are Stable including floating-point cases such as 1 to 1.05; just past the band is Improved or Regressed; informational (neutral) metrics are never classified; a missing side is "not recorded"; reference zero: 0 to 0 is Stable with delta 0, a change away from zero is classified by direction with no percentage.
- Metric identity is key plus dimensions, so two strategies of one scenario never collapse.
- Pairing two scenario metric lists gives rows for the union, marks one-sided metrics not recorded, and produces the summary counts Improved, Stable, Regressed, Incompatible, and Not recorded.
- Headline selection returns only declared summary roles, grouped by scenario in the Run's own order, with the first scenario that declares any as the default and no selection when none does.
- Group titles: known groups get labels, unknown future groups get a readable generic title.
- Formatting: numbers keep the source precision with a sensible cap and thousands separators, units stay attached, durations read as minutes and seconds, timestamps use the console's existing UTC convention (`formatTimestamp`), so operators never depend on a local timezone, and the exact instant is available next to any relative or shortened form, identifiers compact without two different ids becoming identical.

## Implementation Notes

- Reuse the boundary cases the API's tests pin (the ±5% band, direction, missing values) so the two sides share one definition. The reference-zero behavior deliberately follows the approved design, not the API's pure function; record that in the module's documentation.
- Never let a missing value become zero, and never compute a delta across incompatible scenarios.
