# F10 — Baseline selection

## Objective

Let the developer select the Benchmark Baseline from a completed Run and from a comparison, with a confirmation that discloses the Git effect, clear success and failure treatment, and a pending-change notice.

## Acceptance Criteria Served

US-12, US-76..82.

## Affected Files / Areas

- Baseline action, confirmation dialog, and pending-change notice used by the Run detail, the Comparison, and the overview's Baseline line.

## Test-First Plan

- Rendered tests: the action exists only for a completed Run and only when the contract has the Baseline write; running, incomplete, and missing Runs show it absent or disabled with an explanation.
- The confirmation names the current and the proposed Baseline, explains the reviewable Git change, and offers no commit or push; cancel changes nothing and restores focus.
- Success (`PUT`) shows the new Baseline and the pending files the API reports (bounded list and total); selecting the current Baseline again reports "no change".
- Failure keeps the previous Baseline displayed and states the reason for an ineligible Run, an unknown Run, and an unreachable API; the mutation refreshes the Baseline everywhere it is shown.
- The request body carries only the Run id and no credential.

## Implementation Notes

- The browser makes a cross-origin `PUT` with a JSON body; the API's CORS already allows it from the console origin. Verify this once in the smoke test.
- The console never writes anything else and never offers a way to commit.

## Dependencies

F7, F9.

## Completion Signal

A developer can change the Baseline deliberately from the console, sees the reviewable Git change, and a failure never obscures the current reference; tests pass.
