# T4 — Ledger integrity triggers and the global invariant check

## Objective

Enforce the ledger invariants in PostgreSQL itself (ADR 0003) and provide the reusable global-invariant check used by later tests.

## Acceptance Criteria Served

US-53..61.

## Affected Files / Areas

- A new hand-written SQL migration containing the functions and triggers.
- A test helper that asserts the global invariants; hooked into the shared test setup from T2.

## Test-First Plan

Integration tests using direct SQL against the real database (the SQL seam of the PRD). Each must fail before the migration and pass after:
- Unbalanced Ledger Transaction (debit 80, credit 70) fails at commit.
- A Ledger Transaction with no entries, or a single entry, fails at commit.
- A balanced Ledger Transaction with two or more entries commits.
- `UPDATE` and `DELETE` on ledger entries fail; `UPDATE` and `DELETE` on ledger transactions fail.
- The same rules hold when several entries are inserted in one statement and when inserted across several statements in one transaction.
- Global invariant helper: returns clean on an empty ledger and after valid movements; reports a violation when the total of all entries is not zero or when a Wallet Balance is negative (simulate by disabling the trigger only inside the helper's own test).

## Implementation Notes

- Sum-zero and non-empty checks are constraint triggers, deferrable and initially deferred, so all entries of a transaction can be inserted before the check runs at commit. Check the sum with debits positive and credits negative, per Ledger Transaction.
- Immutability is a row-level before-update-or-delete trigger that raises an exception.
- `TRUNCATE` is not covered by row triggers and stays available so the test helper can reset between tests; this is intentional and must be noted in the migration comment.
- The global invariant helper computes the sum of all entries and the Balance per Wallet with plain SQL; it must be cheap enough to run after every database test.
- Keep the SQL readable and commented; it is study material as much as a safeguard.

## Dependencies

T3.

## Completion Signal

All trigger tests pass, the invariant helper is available to all layers, and the helper is invoked automatically after integration and concurrency tests.
