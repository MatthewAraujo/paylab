# T17 — Describe the read endpoints in OpenAPI

## Objective

Make `GET /docs-json` describe every read route (responses, query parameters, errors, Bearer auth) so a generated client (the Operational Console) gets typed contracts.

## Acceptance Criteria Served

New requirement from the Operational Console: a typed contract for `GET /v1/accounts`, `/v1/accounts/:id`, `/v1/accounts/:id/balance`, `/v1/accounts/:id/entries`, `/v1/payments`, `/v1/payments/:id`, `/v1/reports/daily`.

## Affected Files / Areas

- Infra HTTP: response DTO classes with `@ApiProperty`, `@ApiOkResponse`/`@ApiQuery`/`@ApiParam`/`@ApiBearerAuth` decorators on controllers, `.addBearerAuth()` in `app.factory.ts`.
- One contract test over the generated document.

## Test-First Plan

- Contract test: build the Swagger document from the test app and assert that each read route has a `200` JSON response schema resolved to a named component, that list routes declare their query parameters, that `401` is declared, and that a Bearer security scheme exists.
- Presenter views stay the runtime source of truth; the test also checks that a real response's keys match the documented schema properties for at least one route per shape.

## Implementation Notes

- Only the read routes are described in depth; the write routes are out of the console's scope and get only what is free.
- Money fields are documented as integers in centavos.
- Error body is `{ code, message }` for domain errors; validation errors keep the framework shape.
- Swagger stays non-production only (unchanged).

Contract test passes and `pnpm lint`, `pnpm typecheck` and the existing suites are clean.
