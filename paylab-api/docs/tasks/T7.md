# T7 — Merchant provisioning script and API key authentication

## Objective

Create Merchants and API keys by script and authenticate every request by API key, resolving the current Merchant for scoping.

## Acceptance Criteria Served

US-1, US-2, US-3, US-5, US-6, US-7 (the scoping mechanism), US-8 (foundation).

## Affected Files / Areas

- A provisioning script in the scripts folder, modeled on the reference project's owner-creation script.
- Application layer: merchant and API key repositories and an authenticate use case.
- Infra: a Nest guard, a decorator that injects the current Merchant, module wiring, and the Prisma repositories.
- Tests: unit for key generation and hashing, integration for the repositories, e2e for the guard.

## Test-First Plan

- Unit: a generated key has enough entropy and a recognizable prefix; hashing is deterministic; the hash never equals the raw key.
- Integration: only the hash is stored; lookup by hash resolves the Merchant; an unknown hash resolves nothing.
- E2E through a temporary protected route: no key returns 401; an invalid key returns 401; a valid key reaches the handler with the correct Merchant; a key of Merchant A never resolves to Merchant B.
- Script test: running provisioning twice creates two distinct Merchants and prints the key once.

## Implementation Notes

- Send the key in a standard header. Compare hashes with a constant-time comparison.
- Use a fast keyed or plain cryptographic hash suitable for high-entropy random keys; do not use a slow password hash.
- Never log the raw key or the hash.
- Better Auth was removed in T1 and returns in February; do not build user sessions or roles.
- The External Clearing Account already exists from T3; this task does not touch it.

## Dependencies

T1, T3.

## Completion Signal

Provisioning produces a working key, the guard tests pass, and no raw key appears in the database or logs.
