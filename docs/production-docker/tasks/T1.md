# T1 — API production image and initializer target

## Objective
Build a multi-stage production image for `paylab-api` whose final stage holds only the compiled application and production dependencies and runs as a non-root user, plus a separate build target for the one-shot migration/demo initializer.

## Acceptance Criteria Served
AC-8 and AC-9 (API part) in ../PRD.md. Supports AC-7 (initializer target).

## Affected Files / Areas
New production Dockerfile in `paylab-api` beside the unchanged development Dockerfile; existing `.dockerignore` (reuse, change only if it lets secrets or build output in).

## Test-First Plan
- AC-8 → final image lacks `tsc`, `nest`, `ts-node`, `prisma` CLI, vitest and `pnpm` → `docker run` of the built image → catches a single-stage or full-install runtime.
- AC-8 → final image starts `node dist/infra/main` and answers `/health` against a throwaway PostgreSQL with migrations applied → container/HTTP → catches missing Prisma Client/engine or pruned runtime dependency.
- AC-9 → `id -u` in the final image is non-zero → `docker run` → catches root runtime.
- AC-7 → initializer target runs `prisma migrate deploy` and the Docker demo initializer as the `node` user and can write `/run/paylab/api-key` on a fresh named volume → `docker run` with throwaway volume → catches missing CLI or volume ownership.
- AC-12 → no build argument or layer contains environment secrets → `docker history`/build context review → catches `.env` copied into the image.

## Implementation Notes
Pin pnpm from `packageManager` (11.9.0) and use `--frozen-lockfile`. `postinstall` runs `prisma generate`, which needs the CLI: produce production dependencies so the generated client survives (e.g. prune after generate, or install production deps with scripts ignored and copy the generated client). Runtime needs OpenSSL and the Prisma schema. Create `/run/paylab` owned by `node` in the initializer target so a new named volume inherits that ownership. Set `NODE_ENV=production`. Do not modify the development Dockerfile or the initializer script. Use throwaway containers/volumes only; never touch the development volumes.

## Dependencies
None.

## Completion Signal
Both targets build; checks above pass and their commands are recorded in the run summary.
